# 郵件任務與 Telegram 提示

郵件任務使用「郵件閱讀｜主旨」標題。新增成功、已有任務、取消、已讀、保留與封存等已完成操作的提示，以及郵件任務自動排程成功提示，會在成功發送後等待最多七秒再要求 Telegram 刪除。確認、修改、錯誤與進度回報卡片保留供操作。移到垃圾桶沿用不另發成功提示的流程。

任務資料不因提示刪除而移除。透過 `/tasks` 查看郵件連結，透過 `/plan` 調整排程。排程與進度提示採簡短標題；完整主旨仍保留在任務中。舊 `Read email:` 標題只在顯示時轉換，不改寫既有資料。

任務、排程與進度卡片均顯示「開啟郵件」。連結帶有 Gmail 帳號選擇參數；有 RFC Message-ID 時使用精確搜尋，舊來源記錄則相容原始 Gmail ID。Gmail 官方說明支援 [rfc822msgid 搜尋](https://support.google.com/mail/answer/7190)。瀏覽器仍需登入對應帳號；Android/iOS 的原生 Gmail 連結攔截行為須以實機確認，這不是原生應用程式開啟保證。

刪除期限與排程提示清理狀態會保存。Webhook 重試不重發已送達的操作提示；排程提示刪除失敗會由後續 tick 重試。程序中斷、網路與 Telegram 拒絕可能使實際刪除超過七秒。新的進度卡片成功送達後才清理舊排程卡片，避免發送失敗時失去操作入口。

已結束時段不補發「已安排」提示；核對 Calendar 行程後直接詢問進度。未開始回報保留既有重新安排、縮短時段、暫緩與停止安排的選項，不自動推定任務已完成，也不自行新增提醒。

## 郵件中的活動邀請

「加入安排」（舊卡片的 Task）先判斷郵件用途：文章維持閱讀任務確認；競賽、講座或活動邀請依原文公告時段直接建立私人 Calendar 行程，不建立額外閱讀任務。活動名稱與時間必須有原文依據。缺少結束時間、時區或活動資料不完整時，保留郵件卡片並詢問補充；可回覆取消。

活動時段固定，不交給學習排程器另外找時間。有衝突時先詢問，可回覆「仍要加入」接受重疊；不擅自移動原行程。UTC 時間依使用者設定時區顯示。成功或已存在提示沿用七秒清理。

此操作僅建立個人行事曆紀錄，不代表已報名、付款、寄送邀請或回覆主辦方。Calendar 使用固定來源 ID 防止重複，寫入結果不明時只核對原事件，不盲目重建。已修改或取消的事件不會自動覆蓋。活動原郵件可由 Calendar 描述中的來源連結開啟。
