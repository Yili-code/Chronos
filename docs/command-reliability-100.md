## 修正範圍

1. 保留整個下午的說法變體、目標省略與順位／固定 ID 混淆。
2. 明確任務身分、無效編號、否定完成與引用指令；內容欄位中的任務編號及排程錨點保持資料角色。
3. 多章節要求誤入單任務路徑；零休息、修改休息、整日規劃的休息，以及不支援的小數／負數休息。
4. 待確認改排的取消與自然語言進度取消，保留不確定寫入的恢復流程。
5. 今日空檔數量被替換成明日兩小時；改為保留查詢範圍、總分鐘、課前準備與已批准保留。
6. 改名但保留內容的誤擋，以及把未完成狀態寫成內容的誤操作；不允許內容 payload 自行授權改名。
7. 清除確認卡在取消或消耗後仍可再次刪除；單次請求 token、過期及原子收據阻止舊按鈕刪除後來的資料。
8. 成功改排的訊息卡被當成文字再包裝；保留原訊息形狀、解除按鈕及舊卡清理資訊。

## 證據邊界與重跑

以下通過代表指定案例及其狀態斷言通過，並不保證所有自然語言永遠都能理解。Firestore 使用嚴格交易模擬；Calendar 寫入、Telegram 投遞失敗及故障恢復均使用隔離 transport，不是對真實帳號進行破壞性驗證。部署後另外驗證真實 Calendar 讀取與服務版本。

一般離線重跑：

```powershell
python -m pytest -q tests/test_command_reliability.py tests/test_command_pressure.py
```

明確授權真實模型抽樣後，可設定 `CHRONOS_COMMAND_LIVE=1` 執行指定 SQLite 案例。這會透過已登入的 gcloud 讀取模型設定至記憶體，發送固定合成資料，更新模型輸出 fixture；不得加入真實聊天、憑證或個人資料。一般 CI 不設定此旗標，不呼叫外部模型。

測試契約若修正，必須區分原本斷言錯誤與產品缺陷：本次課表衝突、既有時段碰撞、部分進度續讀身分、活動確認 metadata 及剩餘工作語意，皆保留原始觀察並重新驗證，不以放寬生產限制換取綠燈。
